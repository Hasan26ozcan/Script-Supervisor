Limitations & Caveats
IMPORTANT: All results below are from MOCK MODE — no real API calls were made. The mock responses are deterministic placeholders that do not reflect actual model capabilities. • Demo dataset: 20 synthetic preference pairs with 2 fixed templates and 1 rater/item. No real inter-rater reliability (κ) is computable. Use >=2 raters/item for that. • Mock responses: All mock critiques return identical fixed scores (6, 7, 5 for clarity/tone/match). This means quality deltas are always 0.0 and the rubric cannot learn meaningful weights from mock data. • Database backend: PostgreSQL was unavailable (psycopg/libpq issue). All writes fell back to the JSONL file. To test real DB persistence, start Docker: docker compose up -d db • Bradley-Terry: The demo data alternates winners by index parity (odd→A, even→B), so the model correctly reports no detectable strength gap (P=0.5). A harness reporting "94% accuracy" on this data would be misleading. • Heuristic judge: Scores are based on sentence count + action verb hits, not a real LLM judge. Swap for app.rubric.Rubric + live model when mock_mode=False. • Mock mode cost/latency: These are simulated from token counts and pricing tables, not real API responses. Use real API calls to get actual cost data.
